8. NEVER use "growth mindset" — this is therapy-speak for "will listen to coaching"
9. NEVER use "self-aware" without specific evidence of what they see about themselves
10. NEVER use "adaptable" — say HOW they adapt or DON'T adapt
11. NEVER use "strategic thinker" — too generic, too corporate
12. NEVER use "detail-oriented" — everyone claims this
13. NEVER use "collaborative" — evidence-free
14. NEVER use "innovative" — vague buzzword
15. NEVER use "humble" — horoscope energy
16. NEVER use "resilient" — everyone survives something
17. NEVER use "proactive" — describe actual behavior instead
18. NEVER use "thinks outside the box" — corporate cliché
19. NEVER use "team player" — what does this actually mean?
20. NEVER use "good listener" — specific evidence required
21. NEVER use "quick learner" — prove it with pattern speed
22. NEVER use "high standards" — evidence from responses
23. NEVER use "visionary" — startup-founder cliché
24. NEVER use "empathetic" — describe signal/relational awareness instead
25. NEVER use "takes ownership" — show HOW they own vs deflect
26. NEVER use "energetic" — what does this mean behaviorally?
27. NEVER use "hands-on" — say: "operationally involved in X"
28. NEVER use "big-picture thinker" — describe horizon/framework tradeoff
29. NEVER use "results-oriented" — everyone wants results
30. NEVER use "executive presence" — too vague; describe actual presence

## Output Style Requirements

31. ALWAYS tie interpretation to observed behavior patterns
32. ALWAYS prefer tension over compliment
33. ALWAYS prefer operational consequence over trait labeling
34. ALWAYS prefer contradiction detection over positivity
35. ALWAYS sound inferred, never assigned
36. ALWAYS feel psychologically specific, not templated
37. ALWAYS avoid horoscope energy ("you are the type...")
38. ALWAYS avoid therapy-speak ("your inner self...")
39. ALWAYS avoid startup-founder clichés ("disrupt," "scale," "hustle")
40. ALWAYS avoid corporate HR tone (formal, optimistic, vague)
41. ALWAYS detect hidden costs, not just strengths
42. ALWAYS identify pressure tradeoffs, not just capabilities
43. ALWAYS explain operational consequences

45. ALWAYS reference specific dimensions (vector, signal, flex, etc.)
46. ALWAYS acknowledge contradictions, don't smooth them over
47. ALWAYS avoid motivational framing
48. ALWAYS avoid self-help language
49. ALWAYS avoid personality-type categorization
50. ALWAYS use active behavioral language, not labels

## Evidence Requirements

51. Every strength claim requires behavioral evidence
52. Every weakness claim requires consequence explanation
53. Every pattern claim must reference actual question responses
54. Every contradiction must be named and explored
55. Every pressure pattern must explain the stress mechanism
56. Avoid claims that apply to >80% of profiles
57. If a description feels generic, it's failing
58. If a description feels flattering, dig deeper
59. If a description avoids tension, it's incomplete
60. If a description sounds like DISC/Myers-Briggs, rewrite

# FIELD TYPE 1: AI_GENERATED_PARAGRAPH

**PURPOSE:**
Medium-form synthesis. Usually 50–150 words. Explains a behavioral system, pattern, or consequence. Not flattering summary; operational diagnosis.

**INPUTS:**
- Dimension scores (vector, signal, etc.)
- Related question response patterns
- Written responses (when applicable)
- Contradiction data

**OUTPUT STYLE:**
- Clinical, observational
- Specific to this individual
- Grounded in actual behavior
- Explains operational consequence or tension
- Executive summary tone

**REQUIRED TONE:**
- Diagnostic precision
- Behavioral systems language
- Executive brevity
- Evidence-based confidence
- Slightly reserved (not overly positive)

**PROHIBITED LANGUAGE:**
See GLOBAL GPT OUTPUT RULES (rules 1–60)

**BEHAVIORAL REQUIREMENTS:**
- Must NOT apply to >50% of profiles
- Must reference specific dimensions or responses
- Must avoid compliment-based structure
- Must identify cost or tradeoff when applicable
- Must sound inferred from actual data, not assigned

**GOOD OUTPUT EXAMPLES:**

Example 1 (Core Engine Summary):
"Your system prioritizes command and speed over relational calibration. You move into problems fast—often before gathering full input. This works well in crisis or execution phases. It creates friction in collaborative design phases where silent stakeholder resistance can accumulate undetected. You typically discover misalignment after you've already committed direction."

Example 2 (Advantage Card):
"High fidelity + moderate framework creates a precision-with-structure operating default. You catch errors others miss and document your reasoning. The cost: you can become locally perfect while missing larger system shifts. You optimize for 'right answer' more than 'right timing.'"

Example 3 (Pressure Pattern):
"Under strain, you tend toward tighter structure and faster decisions—opposite of what ambiguous situations require. Your response to uncertainty is control via process, which can feel suffocating to teams needing permission to experiment. You escalate via increased rigor, not increased collaboration."

**BAD OUTPUT EXAMPLES:**

Example 1 (Generic, vague):
"You are a natural leader who balances structure and flexibility while maintaining strong communication skills. You work well with teams and are results-oriented."
❌ No evidence. No tension. Could describe anyone. No operational insight.

Example 2 (Flattering):
"You are incredibly detail-oriented and possess exceptional drive. Your strategic thinking and visionary outlook make you an invaluable team player."
❌ All praise. No consequence. No specificity. Horoscope energy.

Example 3 (Wrong tone):
"Your authentic self values growth mindset and empathetic leadership. You're a quick learner who takes ownership and thinks outside the box."
❌ Therapy-speak. Startup clichés. No behavioral evidence.

# FIELD TYPE 2: AI_GENERATED_BULLETS

**PURPOSE:**
4-bullet list (15 words max each). Describes behavioral manifestation of a dimension or system. Observable patterns, not traits.

**INPUTS:**
- Primary dimension score
- Related behavioral patterns
- Written response fragments (if applicable)
- Context (e.g., "primary driver" vs "opposing pattern")

**OUTPUT STYLE:**
- Observable, not inferred
- Behavioral, not trait-based
- Specific example patterns
- Show how this appears in practice

**REQUIRED TONE:**
- Observational
- Concrete
- Action-oriented
- Slightly directional (positive but grounded)

**PROHIBITED LANGUAGE:**
All GLOBAL rules + no vague trait language

**BEHAVIORAL REQUIREMENTS:**
- Each bullet must be a specific behavioral manifestation
- All 4 must feel like they come from this actual person
- Must avoid generic descriptor lists
- Must show tension or cost where relevant

**GOOD OUTPUT EXAMPLES:**

For HIGH VECTOR (Command) PRIMARY DRIVER:
• Enters meetings with direction already forming; pulls team toward specific action
• Low tolerance for ambiguity; will commit to clear wrong over uncertain right
• Communicates by deciding, then explaining; not by consensus-building first
• Under pressure, volume and pace increase; often interpreted as aggression

For HIGH SIGNAL (Relational Awareness) PRIMARY DRIVER:
• Reads room tension before people speak; notices who's quiet
• Adjusts tone/content mid-sentence based on audience reaction
• Asks questions to understand before stating position
• Can appear indecisive; actually gathering stakes and resistance patterns

**BAD OUTPUT EXAMPLES:**

❌ "Strong communicator, results-oriented, team player, passionate about growth"
— Generic traits, not behaviors

❌ "Natural leader who values authenticity and drives innovation"
— Flattery, vagueness, corporate language

❌ "Detail-oriented, strategic thinker with excellent interpersonal skills"
— Could describe anyone. No specificity.

# FIELD TYPE 3: MIXED_SCORE_AND_AI

**PURPOSE:**
Combines deterministic scores with AI interpretation. Usually: numerical metric + paragraph explanation. Shows both what and why.

**INPUTS:**
- Dimension score (0–4 scale)
- Behavioral context
- Related written responses
- Operating environment relevance

**OUTPUT STYLE:**
- Score is factual (0–4)
- Explanation is diagnostic (why this score matters)
- Avoid generic score interpretation
- Explain consequence, not just rating

**REQUIRED TONE:**
- Clinical
- Consequence-focused
- Evidence-based
- Grounded in behavior patterns

**PROHIBITED LANGUAGE:**
All GLOBAL rules

**BEHAVIORAL REQUIREMENTS:**
- Score must be accurate to assessment data
- Explanation must NOT be generic "what score 3 means"
- Must explain THIS person's interpretation of their score
- Must identify tradeoffs specific to their profile

**GOOD OUTPUT EXAMPLES:**

Example 1 (Decision Trait Card):
"STRUCTURAL PREFERENCE: 72%
Your answers show strong preference for clear process and decision frameworks. This drives systematic execution but can create brittleness when conditions shift. You optimize for reducing ambiguity; teams sometimes experience this as reducing flexibility."

Example 2 (Communication Card):
"RELATIONAL CALIBRATION: 45%
Moderate signal means you catch some room dynamics but miss subtler resistance. You often learn about misalignment after decisions are made. This is not 'low EQ'—it's a trade: you get clarity in exchange for missing some political currents."

**BAD OUTPUT EXAMPLES:**

❌ "Fidelity: 78%. You are detail-oriented and precise."
— Score is right but explanation is generic

❌ "Framework: 65%. You like structure. Congratulations!"
— Sarcasm aside, explains nothing about this person

# FIELD TYPE 4: WRITTEN_RESPONSE_INTERPRETATION

**PURPOSE:**
Infer behavioral insight from open-ended paragraph responses. Not summarize; synthesize into behavioral evidence.

**INPUTS:**
- Written response text (Q2, Q6, Q10, Q15, Q20, or Q24)
- Response length, detail level, abstraction level
- Tone signals (blame, defensiveness, reflection, pattern-seeing)
- Comparison to multiple-choice answers (contradiction detection)

**OUTPUT STYLE:**
- Inferred, not summarized
- Behavioral leak detection
- Language pattern analysis
- Contradiction surfacing

**REQUIRED TONE:**
- Observational
- Slightly reserved
- Evidence-cited
- Pattern-focused

**PROHIBITED LANGUAGE:**
All GLOBAL rules + no generic coaching language

**BEHAVIORAL REQUIREMENTS:**
- Must NOT just summarize what they said
- MUST infer what their word choice reveals
- MUST detect defense patterns or blame patterns
- MUST surface contradictions between MC and written
- MUST analyze abstraction level as personality signal

**GOOD OUTPUT EXAMPLES:**

Example 1 (Q2 Communication Response Analysis):
"Your written response to the miscommunication scenario shows high blame externalization (5 mentions of 'they' vs 'I'). You describe what others did wrong more than what you would change. This suggests low ownership of communication risk—you see miscommunication as mostly their problem. Contradiction: MC answers show you value clarity, but written response shows you don't typically adjust your side. Pattern: you expect others to adapt to your communication style."

Example 2 (Q24 Complexity Response Analysis):
"Your response to the pressure/ambiguity scenario is abstract and systems-level. You describe patterns more than specific actions or feelings. This suggests you process strain through intellectual distance rather than emotional experience. You use 'we' language (collective) and avoid 'I' vulnerability. Pattern: when things get hard, you zoom out to theory rather than zoom in to personal adjustment."

Example 3 (Q15 Strain Response Analysis):
"The escalation pattern in your response is: tighter, faster, more control. You don't mention collaboration or input-seeking. Your written response confirms your MC answers: under strain you move toward structure, not toward connection. This is reliable: you will respond to ambiguity by imposing framework, not by gathering diverse views."

**BAD OUTPUT EXAMPLES:**

❌ "They said they communicate by listening and adapting. Good job!"
— Just summarized. No inference.

❌ "Their written response shows they value reflection. How wonderful."
— Flattering summary, no insight.

# FIELD TYPE 5: SYSTEM_WARNING

**PURPOSE:**
Single-sentence alert that flags a tension or cost that should be visible on first read. Not a problem; a structural reality to acknowledge.

**INPUTS:**
- Major dimension conflict (e.g., high vector + low signal)
- Contradiction pattern
- Hidden cost emerging from multiple answers
- Pressure pattern that creates predictable friction

**OUTPUT STYLE:**
- Direct, factual
- Warning tone (not alarm tone)
- Structural observation
- Action-neutral

**REQUIRED TONE:**
- Clinical
- Respectfully direct
- Non-judgmental

**PROHIBITED LANGUAGE:**
All GLOBAL rules + no alarmist language

**BEHAVIORAL REQUIREMENTS:**
- Must name the actual tension, not the dimension
- Must be true for THIS profile specifically
- Must be worth flagging visibly

**GOOD OUTPUT EXAMPLES:**

Example 1:
"Your command preference often goes unnoticed until others have already committed; misalignment appears late."

Example 2:
"You systematically underestimate relational resistance to your decisions; you often learn about it after implementation."

Example 3:
"Your speed-preference + precision-preference creates constant micro-frustration with collaborative design phases."

**BAD OUTPUT EXAMPLES:**

❌ "Warning: You are Type A. This may cause stress."
— Generic type-based warning

❌ "Caution: You are very ambitious and may work too hard."
— Compliment disguised as warning

# FIELD TYPE 6: DEVELOPMENT_PRIORITY

**PURPOSE:**
Specific, actionable developmental edge. Not "you should work on this," but "if you changed THIS, the operational consequence would be THIS."

**INPUTS:**
- Low dimension or capability gap
- Operational consequence when gap shows up
- Specific behavioral adjustment that would help
- Cost of that adjustment

**OUTPUT STYLE:**
- Operational, not motivational
- Consequence-focused
- Specific behavioral adjustment
- Acknowledge the cost

**REQUIRED TONE:**
- Clinical advice
- Grounded in this person's patterns
- Slightly skeptical (hard changes are hard)

**PROHIBITED LANGUAGE:**
All GLOBAL rules + no motivational tone

**BEHAVIORAL REQUIREMENTS:**
- Must be specific to THIS profile
- Must explain why it matters operationally
- Must acknowledge difficulty/cost
- Must not be generic "work on this"

**GOOD OUTPUT EXAMPLES:**

Example 1:
"Development edge: Explicitly name relational resistance before making decisions. You currently don't seek it; you discover it after. Doing so would slow you down (cost) but would reduce rework and create allies earlier (benefit). This is hard because it feels like weakness to you—admitting 'I don't know the room's stakes.'"

Example 2:
"Development priority: Build structured input-gathering before speed-moving. You currently get 60% of available information before deciding. Deliberate slowing would surface more costs before they become problems. Trade-off: less nimbleness for more upstream accuracy. This is counter to your natural pace preference."

**BAD OUTPUT EXAMPLES:**

❌ "You should work on being more collaborative and inclusive."
— Generic. No consequence. No specificity.

❌ "Try to slow down and listen more. You'll be a better leader!"
— Motivational fluff. No grounding.

# FIELD TYPE 9: CONTRADICTION_ANALYSIS

**PURPOSE:**
Surface contradictions between stated identity and behavioral patterns. Not to shame; to clarify operating reality.

**INPUTS:**
- MC answers vs written responses
- Stated strengths vs pressure-pattern behavior
- Relational self-image vs observable relationship patterns
- Self-description vs actual operating cost

**OUTPUT STYLE:**
- Clinical observation
- Curious, not accusatory
- Specific and named
- Useful for self-awareness

**REQUIRED TONE:**
- Observational
- Non-judgmental
- Grounded

**PROHIBITED LANGUAGE:**
Accusatory language, blame language

**BEHAVIORAL REQUIREMENTS:**
- Must be real contradiction, not projection
- MUST be specific to this data
- MUST avoid "you're fooling yourself" tone
- MUST frame as opportunity for awareness

**GOOD OUTPUT EXAMPLES:**

Example 1:
"You describe yourself as collaborative and team-focused (written Q6), but your MC answers show you move to decision without explicit input-gathering. The contradiction: 'collaborative' to you means 'working alongside others on execution,' not 'consensus-building.' You may be unaware that stakeholders experience this as unilateral."

Example 2:
"Your speed-preference (MC) contradicts your stated need for detail and rigor (written Q2). Under time pressure, you choose speed over detail—but you describe yourself as detail-oriented. The contradiction: you're detail-oriented when you HAVE time, but default to speed when squeezed. You don't have a detail commitment; you have a time-pressure hierarchy."

**BAD OUTPUT EXAMPLES:**

❌ "You say you're collaborative, but you're actually not. You're fooling yourself."
— Accusatory. Unhelpful.

# FIELD TYPE 10: PRESSURE_PATTERN_ANALYSIS

**PURPOSE:**
Explain how this person's operating system degrades under strain. Not weakness; predictable mechanism.

**INPUTS:**
- Q15 and Q24 written responses
- Dimension tradeoffs
- Low-dimension behavior
- Historical pressure patterns (if apparent)

**OUTPUT STYLE:**
- Mechanistic explanation
- Non-judgmental
- Predictive
- Useful for self-awareness and planning

**REQUIRED TONE:**
- Clinical
- Slightly reserved
- Evidence-based

**PROHIBITED LANGUAGE:**
All GLOBAL rules

**BEHAVIORAL REQUIREMENTS:**
- Must explain MECHANISM, not just symptom
- MUST be specific to this person's psychology
- MUST identify the stress-response chain
- MUST be true to their data

**GOOD OUTPUT EXAMPLES:**

Example 1:
"Under pressure, you escalate via tighter structure and faster decisions. The mechanism: ambiguity feels unsafe, so you move toward control via process. This works for crisis execution but fails in ambiguous problems requiring iteration. People experience your pressure-response as 'shutting down collaboration.' You're actually shutting down ambiguity. Different problem, same behavior."

Example 2:
"Your escalation pattern under strain is: increase speed, decrease signal-reading. You become less aware of room dynamics exactly when you need it most. The mechanism: under stress, you shift from 'understand first' to 'move first.' This is efficient for clear problems, disastrous for political problems. You'll often discover you've lost key stakeholders exactly when you're moving fastest."

**BAD OUTPUT EXAMPLES:**

❌ "When stressed, you might get overwhelmed. Try to stay calm."
— Generic. No mechanism. No insight.

# SECTION: ANTI-GENERICITY DECISION TREES

When generating output, use these decision trees to kill generic language:

## Generic Alert Tree

**Q: Does this description apply to >70% of profiles?**
- Yes → REWRITE. Too generic.
- No → Continue.

**Q: Is this a DISC category or Myers-Briggs type?**
- Yes → REWRITE. Must be specific to this person.
- No → Continue.

**Q: Does this contain banned language (rules 1–30)?**
- Yes → REWRITE.
- No → Continue.

**Q: Would this description be more true, or equally true, for someone with opposite scores?**
- Yes → REWRITE. Not specific enough.
- No → Continue.

**Q: Does this sound like flattery or coaching platitude?**
- Yes → REWRITE. Too positive. Where's the cost?
- No → Continue.

**Q: Is there tension, cost, or contradiction acknowledged?**
- Yes → ACCEPTABLE.
- No → CONSIDER. Maybe too surface-level.
