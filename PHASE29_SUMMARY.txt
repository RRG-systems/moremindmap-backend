================================================================================
                          KEY COMPONENTS
================================================================================

1. RUN ID SYSTEM
   - Format: timestamp-based (e.g., "2026-04-16-12-32-45")
   - Globally unique, chronologically sortable
   - Generated on startup and on reset

2. RUN FINALIZATION
   - Called before any state reset
   - Captures: trades, win_rate, pnl, slippage, sign_flips
   - Appends one row to research_runs.csv

3. RUN SEPARATORS
   - Added to all trade-related CSVs
   - Format: run_id, timestamp, "RUN_SEPARATOR", ...
   - Creates clear boundaries between runs

4. STATE RESET
   - Clears equity curves
   - Resets trade counters and PnL accumulators
   - Reinitializes with $10,000 starting value

5. DATA MIGRATION
   - Runs on DataLayer.initialize()
   - Adds run_id to existing CSVs
   - Backfills with "phase_28_run" identifier

================================================================================

POST /api/reset Execution Order (MUST NOT CHANGE):

1. FINALIZE CURRENT RUN

2. GENERATE NEW RUN_ID

   → Store in simulator.current_run_id

   → simulator.reset_run_state()
   → Clear all equity curves
