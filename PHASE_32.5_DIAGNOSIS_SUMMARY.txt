================================================================================
THE PROBLEM
================================================================================

When user clicked "New Run" button:
- System WAS executing trades (PnL updated, equity curves updated)
- BUT UI metrics showed stale values:
  * total_trades = ~1000 (prior run data)
  * trade_sign_flips = old values
  * flip_rate = incorrect

This indicated split state: execution working, metrics poisoned.

================================================================================
ROOT CAUSE: DATA LAYER CACHE NOT INVALIDATED
================================================================================

EXACT BREAK POINT:
File: dashboard_data_layer.py, line 110
Function: get_recent_trades()

Code:
    def get_recent_trades(self, limit=30):
        non_separators = [t for t in self.trades if t.get('asset') != 'RUN_SEPARATOR']
        return non_separators[-limit:] if non_separators else []

Problem: self.trades list is:
- Loaded from CSV at initialization
- NEVER cleared after reset
- Contains all 1000+ trades from prior runs

When "New Run" clicked, the endpoint:
1. ✅ Appended CSV separator (correct)
2. ✅ Reset ExecutionSimulator state (paper_pnl, paper_trades, etc.)
3. ❌ DID NOT clear DataLayer.self.trades memory cache
4. ❌ UI reads from stale cache, shows old trade count

DUAL SOURCE OF TRUTH:
- ExecutionSimulator.paper_trades: Reset to 0 ✅
- DataLayer.self.trades: NOT reset, still 1000 ❌
- UI reads from DataLayer, shows wrong metric ❌

KEY INSIGHT
================================================================================

System execution was correct — metrics layer was broken.

This is a classic cache invalidation problem:
- Cache (DataLayer.self.trades) not invalidated on state reset
- UI reading stale cache data
- Result: UI lied about metrics while system worked correctly

Prevention: Always clear ALL dependent caches when resetting source data.
