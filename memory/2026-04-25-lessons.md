# Lessons Learned — Apr 25, 2026

## What Worked

### 1. File-Based Message Sync > Polling Complexity
- Initially tried query queue + polling with `query_id` tracking
- Frontend couldn't reliably track state, polling kept timing out
- **Solution:** Unified JSONL message stream, simple append-only log
- **Lesson:** File sync is more reliable than stateful polling. JSON lines is perfect for this.

### 2. Bidirectional > Request/Response
- Started with `/api/think/query` endpoint expecting responses via webhook
- Operator (me) had to manually respond via Python bridge
- **Solution:** Unified stream where everything I type here auto-syncs to THINK
- **Lesson:** One conversation thread beats two interfaces. Chat here IS the THINK feed.

### 3. Random Startup Messages > Canned Dialogue
- You explicitly said "no templates" — natural conversation only
- Added 40+ random entrance messages instead
- **Lesson:** Personality scales. Randomness beats templates. Each session feels unique.

### 4. Calibration on Demand > Pre-computed Rules
- Could have hard-coded "if win_rate > 55% then AGGRESSIVE"
- Instead built endpoint that applies any style instantly
- **Lesson:** Give operator (you) the lever. Don't automate away the decision. You own the style choice.

### 5. BRAIN Calibration Affects Baby Generation, Not Just Execution
- Initial confusion: "Does calibration change BRAIN's execution or baby parameters?"
- **Answer:** Both. Calibrated BRAIN config gets read by mutation engine. New babies inherit tuned thresholds.
- **Lesson:** Calibration is genetic. Past babies don't change, but future babies are smarter.

## What Broke (And Why It's Important)

### 1. Query Queue + Frontend Polling Failed
- Built `think_query_monitor.py` to check `/tmp/think_queries.json` every second
- Frontend polling for `query_id` responses kept timing out
- **Why:** Stateful tracking (query_id) is fragile when you have async frontend + backend
- **Lesson:** Don't fight the state machine. Use append-only logs, not query tracking.

### 2. Manual Response Bridge Was Painful
- You had to tell me "I asked THINK a question" so I could respond via Python
- Late by 30 seconds every time
- **Why:** Operators shouldn't have to coordinate message flow manually
- **Lesson:** Automate the notification. Don't make the operator wait.

### 3. BRAIN Calibration Config Didn't Apply on First Call
- Applied AGGRESSIVE calibration, but BRAIN stayed in THROTTLE
- Reason: BRAIN logic wasn't reading the new config, it was stale in memory
- **Why:** State in memory ≠ state on disk. Need to restart to reload.
- **Lesson:** For production systems, either hot-reload config or document the restart requirement clearly.

### 4. Arena Metrics Endpoint Broken
- `/api/arena/metrics` returns 404
- Can't see Arena performance directly
- **Why:** Endpoint exists but isn't wired, or data layer is missing
- **Lesson:** Test all endpoints during integration, not after. One broken endpoint breaks diagnostics.

## Technical Decisions That Paid Off

### 1. JSONL for Messages
- Append-only (no state conflicts)
- Human-readable (can grep for bugs)
- Portable (file-based, no DB)
- **Result:** Zero polling bugs, easy to debug, survives app crashes

### 2. Three Calibration Modes (Not N Modes)
- Resistance to over-engineering
- Conservative/Moderate/Aggressive is simple decision tree
- **Result:** Easy to teach, easy to choose, clear trade-offs

### 3. Entrance Messages Are Deterministic Random
- Same file, different message each time
- Not pulling from API, just `random.choice()`
- **Result:** Fast, reliable, no external dependencies

### 4. No Database for Sessions
- Could have used SQLite or Postgres
- Chose file-based JSONL
- **Result:** Portable, debuggable, no deployment overhead
