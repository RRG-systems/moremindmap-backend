## EXECUTION REALITY AUDIT — CRITICAL FINDINGS

**Time:** 17:16-17:50 MST  
**Status:** AUDIT COMPLETE — EXECUTION MODEL HAS CRITICAL GAPS

### Key Findings

**1. Execution Path (Traced)**
- Bot → `on_universe_tick()` → `List[Order]`
- Order → `place_orders()` → Fill at bid/ask
- Fill → PnL calculation (no costs)
- Paper vs Shadow → hardcoded to 0.0 (placeholder)

**2. Fill Realism: LOW**
- BUY fills at `market.ask` exactly
- SELL fills at `market.bid` exactly
- Comment in code: "Deterministic fills, no latency/slippage simulation"
- **Reality:** Zero slippage assumed (FAKE)

**3. Slippage Model: MISSING**
- Code: `fill_price = market.ask` (no adjustment)
- Should be: `fill_price = market.ask + slippage`
- Currently: 0 bps assumed
- Reality: 0.5-2 bps per trade
- **Risk:** 25-100 bps fake profit over 50 trades

**4. Order Book Depth: MEASURED BUT UNUSED**
- Depth data exists: `bid_size`, `ask_size` in MarketSnapshot
- Fill logic: Ignores depth completely
- **Reality:** 1000 share order at 10 share depth = partial fill + slippage
- **Model:** Always fills at full size

**5. Paper vs Shadow: NOT DIFFERENTIATED**
- Both have identical execution (bid/ask fills)
- paper_vs_shadow_delta = 0.0 (hardcoded placeholder)
- **Should be:** Paper +0 friction, Shadow +1-2 bps friction
- **Is:** Both +0 friction

**6. Fake Profits Risk: HIGH**
- Model edge: +50 bps
- With realistic costs: -50 to -150 bps
- **Danger:** Mutations breed losing bots that look good in sim

### Critical Gaps

| Aspect | Model | Reality | Gap |
|--------|-------|---------|-----|
| Entry slippage | 0 | 0.5-2 bps | -0.5 to -2 bps |
| Exit slippage | 0 | 0.5-2 bps | -0.5 to -2 bps |
| Fees | 0 | 0.5-1 bps | -0.5 to -1 bps |
| Depth impact | ignored | 0-1 bps | -0 to -1 bps |
| **Total per trade** | **0** | **1.5-6 bps** | **-1.5 to -6 bps** |
| **Over 50 trades** | **0** | **75-300 bps** | **-75 to -300 bps** |

### Minimum Fixes (Priority)

1. **Apply bid-ask slippage** (10 lines)
   - `fill_price = market.ask + (spread * 0.5)` for BUY
   - Impact: Adds 0.25-1 bps per trade

2. **Check order size vs depth** (15 lines)
   - If `order.size > market.ask_size`, apply penalty
   - Impact: Prevents unrealistic large fills

3. **Add trading fees** (5 lines)
   - 0.5-1 bps per trade, both sides
   - Impact: Grounds model in real costs

Total effort: ~30 lines, ~1-2 hours
Benefit: Mutations become reliable

### Assessment

**Is execution realistic for mutation decisions?**

**NO.** Not yet. Too optimistic by 25-200 bps per run.

**Safe for:** Relative ranking, parameter sensitivity
**NOT safe for:** Deployment decisions, absolute edge

**Next action:** Implement 3 critical fixes before Mutation Brain ships.

## ROLLING EDGE CALCULATIONS + PROFITABILITY GUARD — IMPLEMENTED ✓

**Time:** 20:20-20:40 MST

### Problem

Two frozen panels:
- **ROLLING EDGE (20-TRADE)** — showing 0.00 bps (not calculated)
- **ROLLING EDGE (50-TRADE)** — showing 0.00 bps (not calculated)

### Root Cause

Rolling edge metrics were not being calculated in `update_metrics()`. Calculations simply didn't exist in backend.

### The Fix

Added to `update_metrics()` function:

**20-trade rolling window:**
- Extract last 20 trades from segment
- Calculate win rate + avg win + avg loss
- Compute edge = (win_rate × avg_win) - ((1 - win_rate) × avg_loss)
- Store in dashboard_state['metrics']

**50-trade rolling window:**
- Extract last 50 trades
- Calculate edge, drawdown, recovery
- Store in dashboard_state['metrics']

**Result:** Metrics now recalculate on every `update_metrics()` call (which fires after New Run).

### Profitability Guard

Also updated evaluation logic to prevent fake-edge bots from passing:

**Before:** Checked if `avg_pnl > 0` (vulnerable to execution model gap)
**After:** Checks if `(avg_pnl - 3_bps_friction) > 2_bps` (realistic execution costs)

- 3 bps per trade = conservative execution friction estimate
- 2 bps minimum = margin of safety threshold
- Result: Only genuinely profitable bots pass evaluation

**Example:**
- Bot shows 5 bps in simulator
- Apply -3 bps realistic costs
- Realistic edge = 2 bps
- Decision: PASS ✓

- Bot shows 2 bps in simulator
- Apply -3 bps realistic costs  
- Realistic edge = -1 bps
- Decision: FAIL ✗
