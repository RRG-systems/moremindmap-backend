### Vault Architecture

**Profile ID format:** `MM-YYYYMMDD-XXXXXXXX`
- MM = MoreMindMap prefix
- YYYYMMDD = Creation date
- XXXXXXXX = 8-char random alphanumeric (lowercase)
- Example: MM-20260521-gknmgkf5

**Redis key structure:**
```
vault:profile:{profile_id} → Full vault record (~27KB)
vault:markdown:{profile_id} → Markdown dossier (~26KB)
vault:index:date:{YYYY-MM-DD} → Profile IDs by date
vault:index:email:{email} → Profile IDs by email
```

## Key Learnings

### 1. Evidence Weighting Hierarchy
**Most reliable evidence (Tier 1):**
- Stress answers (Q17, Q24)
- Contradictions between answers
- Business numbers (Q26)

**Least reliable (Tier 5-6):**
- Direct self-description
- Isolated claims
- Aspirational language

**Application:** Weight stress/contradiction evidence higher than calm self-reports.

### 2. Consequence Modeling > Trait Description
**What works:**
- "Relational damage accumulates invisibly during execution sprints; repair becomes necessary every 4-6 months"
- "Growth plateaus at personal execution limit within 18-24 months"

**What doesn't work:**
- "You're a natural leader"
- "You care deeply about people"
- Generic DISC language

**Lesson:** Predict WHERE BEHAVIOR LEADS, not just what it IS.

### 3. Profile_id Architecture
**Why company NOT embedded in profile_id:**
- Individual assessments can cross companies (job changes)
- One person may have profiles from multiple organizations
- Profile_id should be permanent/immutable
- Company affiliation is metadata, not identity

**Lesson:** Design IDs for permanence, store context as indexed metadata.

### 4. Production Wiring with Fallback
**Pattern that works:**
```javascript
try {
  // New feature (canonical generation)
} catch (error) {
  // Log error, continue to existing flow
  return { success: true, nextStage: NEXT_STAGE }
}
```

**Result:** New features never crash existing pipeline.

**Lesson:** Insert features with graceful degradation, not replacement.

### 5. Encrypted Environment Variables
**Gotcha:** `vercel env pull` shows encrypted values as empty strings

**Solution:** Use `vercel env ls` to verify presence, not `vercel env pull` for value inspection

**Lesson:** Don't trust local `.env` files for production verification; use runtime diagnostics.
